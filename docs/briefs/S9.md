and refuses a total when coverage is insufficient. Scores measure writing-process quality, not scientific
validity, and are provisional until calibrated (PRD §12).

## 1. Core — `src/core/scoring/`

- `rubric.ts`: `RUBRIC_VERSION = 'schimel-paragraph-v1'`; `DIMENSIONS` in this order with weights summing to 1:
  `sentence_structure` 0.25 (Schimel Ch. 12), `verb_word_choice` 0.20 (Ch. 14–15), `concision_modifiers` 0.15
  (Ch. 16), `paragraph_organization` 0.20 (Ch. 11), `flow_coherence` 0.20 (Ch. 13). For each dimension a Vietnamese
  label and five level descriptors 0–4 (0 not supported / major breakdown, 1 substantial problems, 2 mixed, 3 good,
  4 highly effective), written specifically for that dimension. `NOT_ASSESSABLE_LIMIT = 2`.
- `availability.ts`: `assessability(analysis)` → per dimension `{ applicable: boolean, reason: string | null }`,
  decided by code only:
  - `sentence_structure`: needs S5 sentence annotations for every sentence.
  - `verb_word_choice`, `concision_modifiers`: always assessable once the text is split (detectors run locally).
  - `paragraph_organization`, `flow_coherence`: need the S8 paragraph result; `flow_coherence` also needs ≥ 2
    sentences and ≥ 1 measured pair.
  - Reasons in Vietnamese, e.g. "Cần phân tích câu", "Cần phân tích cấu trúc đoạn", "Đoạn chỉ có một câu".
- `evidencePackage.ts`: builds, per applicable dimension, the inputs the model sees: the relevant metrics with
  denominators and the relevant issues (id, type, quoted span, severity, status). **Dismissed-by-human issues are
  excluded**; confirmed-by-human issues are marked as such; AI-acceptable (`info`) issues are listed as acceptable.
- `computeScores(raw, assessability, issues, analysisMeta)` →
  `{ rubricVersion, dimensions: DimensionScore[], overall: number | null, overallSuppressedReason: string | null,
coverage: { applicable, total, value }, confidence: number | null, contextLimited }` where
  - `DimensionScore = { id, label, weight, applicable, notAssessableReason, rubric: 0..4 | null, score: number | null,
descriptor: string | null, confidence: number | null, evidence: { issueIds: string[], sentenceIds: string[] },
rationale: string | null }`;
  - `score = rubric / 4 * 100` (one decimal); a dimension the code marks not applicable stays not applicable even if
    the model returns a level; a model `rubric: null` makes it not applicable with reason "AI không đủ căn cứ";
  - `overall` = weighted mean of applicable scores with weights renormalised over applicable dimensions (one
    decimal); `null` with reason "Không tính điểm tổng: N tiêu chí chưa đánh giá được (ngưỡng 2)" when the number
    of not-applicable dimensions ≥ `NOT_ASSESSABLE_LIMIT`;
  - `confidence` = weight-renormalised mean of applicable dimension confidences (null if none);
  - evidence ids that do not exist (or point at dismissed issues) are dropped; sentence ids validated.
- `issueSnapshot(issues)`: a deterministic string of `id:status:severity` sorted, stored with the scores; scores are
  **stale** when the current snapshot differs (human decisions after scoring).

## 2. Prompt and provider

- `src/core/prompts/scoring.ts`: `PROMPT_VERSIONS.scoring = 'score-1'`; `buildScoringPrompt(text, packages,
rubric, context)`; `ScoringOutputSchema`: `{ dimensions: [{ id, rubric: 0|1|2|3|4|null, confidence, evidenceIssueIds:
string[], evidenceSentenceIds: string[], rationale }] }`. System prompt (English): score only the listed applicable
  dimensions with the given descriptors; prioritise recurring, consequential problems over incidental style; never
  deduct per count; passive voice, hedges and necessary qualifiers are not faults by themselves; cite issue ids and
  sentence ids as evidence; use null when evidence is insufficient; rationale in Vietnamese; never invent issues,
  numbers or offsets.
- `src/shared/llm/llmScorer.ts`: one call (temperature 0) → validated through core → `{ scores, model,
promptVersion }`.

## 3. Schema and storage

- `Analysis.scores` (default `null`) with the shape above plus `issueSnapshot`; `versions.rubric` set to
  `RUBRIC_VERSION` when scored; add `versions.scoringPrompt` and `versions.scoringModel` (defaults null). Old records
  parse. Save / reopen without a model call; re-running syntax or structure, or editing the text, clears the scores.

## 4. UI

- Toolbar: `Chấm điểm (AI)` (consent-gated, cancellable), enabled once the text is split and no other AI action is
  running; disabled after saving like the other AI buttons.
- New tab `Điểm` in the document column (after `Cấu trúc đoạn`):
  - Header line, never a bare number: "Tổng 68,5 / 100 · Phủ 4/5 tiêu chí · Tin cậy 70 % · Rubric
    schimel-paragraph-v1 · context_limited" — or, when suppressed, "Chưa tính điểm tổng" with the reason, while
    still showing the dimension scores.
  - One row per dimension: label, weight, score with a bar (number shown, not colour only), rubric level and its
    descriptor, confidence; not-applicable rows show "Chưa đánh giá được" + reason and an action hint (e.g. "Chạy
    Phân tích cấu trúc đoạn").
  - Expanding a row shows the rationale and the evidence as chips; clicking an issue chip selects that issue (card
    and highlight), clicking a sentence chip scrolls to the sentence.
  - A permanent note: "Điểm đo chất lượng diễn đạt theo rubric thử nghiệm, chưa hiệu chuẩn; không đánh giá tính
    đúng khoa học."
  - When stale: a notice "Điểm có thể đã cũ do bạn vừa xác nhận/bỏ qua gợi ý — chấm lại để cập nhật".

## 5. Tests (IDs in names)

- `AC-10`: two not-applicable dimensions → `overall: null` with the reason; one not-applicable → overall computed
  with renormalised weights (check the exact number on a fixture).
- `EV-09`: `score = rubric/4*100`; confidence renormalisation; coverage `{ applicable, total, value }`; the model
  cannot make a code-not-applicable dimension applicable; `rubric: null` → not applicable; unknown and dismissed
  evidence ids dropped.
- Evidence package: dismissed issues excluded, confirmed marked, acceptable listed as acceptable.
- Staleness: a decision after scoring changes the snapshot → stale.
- `AC-09`-style: the prompt states that counts are not deductions and passive voice is not a fault (assert prompt
  text).
- Provider: one call, versions returned.
- UI (fake client): button gating; `Điểm` tab header with coverage / confidence / rubric; suppressed total message
  when structure was not run; evidence chip selects the issue; stale notice after a confirm; save → reopen without a
  model call.
- Coverage ≥ 90 % lines for `src/core/**` and `src/shared/llm/**`; all existing tests pass.
