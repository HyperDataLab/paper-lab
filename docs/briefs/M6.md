Why: the model goes straight from paragraphs to structured fields. An atomic sentence is a short, self-contained, source-anchored statement a person can check on its own. It adds a checkable layer between the paper and the profile, in the same extraction call, so the number of AI calls does not grow.

## 1. Schema (old stored runs and checkpoints must still parse)

- `ExtractionOutputSchema` gains `atomic_sentences: { key, text, role: 'background' | 'method' | 'finding' | 'limitation', quote: QuoteRef }[]` (default `[]`).
- `ModelFieldSchema`, model results and model claims gain `atom_keys: string[]` (default `[]`).
- Profile gains `atomic_sentences` (default `[]`): `{ id: 'as-0001', text, role, word_count, evidence_id, page, section_id, needs_review, human_checked }`.
- `ProfileField`, `ReportedResult`, `ResearchClaim` gain `atomic_ids: string[]` (default `[]`).
- `discarded` gains `atomic_too_long`, `atomic_quote_not_found`, `atomic_number_not_in_source` (each default 0).

## 2. Prompt

Bump `measurementExtract` to `measure-extract-2`. Add rules: at most 30 atomic sentences per part, only statements about what is measured, how, and with what result or limit. Each is at most 25 words, one proposition, understandable alone (name the subject, no "this" or "it" pointing outside the sentence), keeps the key numbers and units exactly, has no citation markers and does not name a table or figure number. `quote` is verbatim, as for other quotes. Fields, results and claims list the `atom_keys` they rest on. Raise `EXTRACTION_TIMEOUT_MS` to 240 s.

## 3. Verification in code (`verify.ts` / `build.ts`)

An atomic sentence is **discarded, never edited**, and counted in `discarded`, when:

1. It has more than 25 whitespace-separated words (`atomic_too_long`).
2. Its quote is not found by the verifier (`atomic_quote_not_found`).
3. A number in its text does not occur in its source (`atomic_number_not_in_source`). Use `containsExact`. The source is the evidence excerpt; for a table cell, also that cell's row and `cellContext`. Ignore citation-style markers such as `[12]` when reading numbers.

Identical sentences (normalised) keep one entry. `needs_review` comes from the evidence. Keys are scoped to their unit; a key pointing at a discarded or unknown sentence is dropped. **A field's status does not depend on its atoms**: §5 of the PRD still decides it. Page and section come from the evidence, never from the model. `mergeFields` and `mergeMetric` union `atomic_ids` when values are merged.

## 4. Review and export

- `reviewedProfile` handles atomic sentences as items: `accept` sets `human_checked: true` and `needs_review: false`; a rejected sentence is removed in exports and its id removed from every `atomic_ids`. The AI original stays untouched.
- `export.ts`: Markdown gets a section `## Câu nguyên tử` grouped by role, each line with page and whether a person checked it. New `atomicCsv(profile)` with columns `id, role, text, word_count, page, section, human_checked, needs_review, evidence`.

## 5. UI

- Tree: a root `Câu nguyên tử` (count) with one child per role that has sentences (`Bối cảnh`, `Phương pháp`, `Kết quả`, `Hạn chế`), then the sentences. Add the needed `MeasurementRef` kinds; ids stay unique.
- Root detail: progress `Đã đối chiếu x/y` and a one-line reminder that code checks the quote and numbers, while only a person can judge whether the sentence says what the source says.
- Role detail: the list of its sentences, each opening its own detail.
- Sentence detail: the text, role, word count, evidence link with page, the items that use it (links), and actions `Đã đối chiếu với nguồn` (accept), `Loại bỏ`, and undo. Extend `ItemActions` with an optional accept label; do not change other callers' labels.
- Result, claim and field rows show links to their atomic sentences when they have any.
- Overview: add one count button for atomic sentences. The export row gets `CSV câu nguyên tử`.

## 6. Tests (IDs in names, synthetic text only)
