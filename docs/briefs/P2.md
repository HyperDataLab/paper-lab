## 1. Section-aware prompts (new versions, old ones unchanged)

- `cand-judge-paper-1`: the S6 judge prompt plus `Section role: {role}` and short per-role conventions (Methods:
  passive voice and procedure verbs such as "were conducted" are normal; Results: report values with units and
  statistics, little interpretation; Abstract: compact, no citations expected; Introduction: context and gap;
  Discussion: hedging is expected; other roles: none).
- `para-struct-paper-1`: the S8 prompt plus `Previous paragraph ends with: "…"` / `Next paragraph starts with: "…"` and
  the section role; `context_limited` is false when both neighbours exist.
- `sent-syntax-paper-1`: the S5 prompt with the section heading; batches of ≤ 40 sentences per call within one
  section (several short paragraphs of the same section may share a call; results are split back per paragraph by
  sentence id).
- `score-paper-1`: the S9 prompt plus the section role (rubric unchanged).
- Builders take an optional `PaperContext = { role, heading, previousLast: string | null, nextFirst: string | null }`;
  without it they produce exactly the current prompts and versions (existing tests unchanged).

## 2. Core — `src/core/batch/`

- `planRun(paper, { sectionIds, steps, budget })` → `RunPlan`: body paragraphs only (captions, equations, references,
  footnotes, headings skipped with reason); `steps ⊆ ['syntax', 'judge', 'structure', 'score']` (detectors always run);
  call estimate per step (syntax by 40-sentence batches per section; judge, structure, score one call per paragraph
  each) and total; `withinBudget`.
- `PaperRun` (Zod): `{ id, paperId, createdAt, updatedAt, status: 'idle'|'running'|'paused'|'cancelled'|'done'|
'budget_exceeded'|'failed', plan, budget, callsUsed, promptVersions, model, items: [{ paragraphId, textHash, analysisId |
null, status: 'pending'|'running'|'done'|'failed'|'skipped'|'cached', stepsDone: string[], calls, error | null }] }`.
- `runBatch(run, deps, signal)`: pure orchestration with injected `deps` (`analyze(paragraph, context, steps)`,
  `save(run)`, `now`, `sleep`): sequential (concurrency 1), checkpoint (`save`) after each paragraph and each step;
  retry a step up to 3 times with exponential backoff on 429 / 5xx / network errors, not on 4xx validation errors;
  stop with `budget_exceeded` before a call that would exceed the budget (remaining items stay `pending`); `pause`,
  `resume` (continues from the first non-done item and the first missing step), `cancel`; a failed paragraph does not
  stop the run.
- Cache: an item whose `textHash` and prompt versions match an existing analysis of the same paper is `cached` and
  reuses it (no calls).
- Paragraph analyses: created through the repository with `origin = { kind: 'paper', paperId, paragraphId }` (extend the
  origin union, old data valid), `context.before/after` from neighbours, `contextLimited` false when both exist, title
  `{section heading} · {paragraph id}`. A re-run updates the same analysis and keeps human review decisions
  (`mergeHumanDecisions`).

## 4. UI — paper map (`/papers/:id`)

- A "Phân tích hàng loạt" panel: section checkboxes (with role badge and body paragraph count; none selected by
  default), step checkboxes (Phân tích câu, Đánh giá ngữ cảnh, Cấu trúc đoạn, Chấm điểm), budget field (default 150),
  a live estimate "Ước tính ~N lượt gọi AI (giới hạn M)", a warning when over budget; `Bắt đầu` (consent-gated with the
  whole-manuscript consent text: a new consent version stating that the selected paragraphs are sent to the configured
  model), `Tạm dừng`, `Tiếp tục`, `Huỷ`.
- Progress: overall bar with numbers, per-section progress, per-paragraph status badge (text + icon) in the centre
  list; failed items show the described error and a "Thử lại" action.
- Results in the map: per paragraph the number of open issues and the score (if scored) with a link "Mở trong Đánh
  giá" (`/evaluate?id=<analysisId>`); Evaluate shows a breadcrumb back to the paper and section.
- Local detectors: after import (and on demand) every body paragraph shows its detector candidate count without any AI
  call.
- A run in progress survives a reload: on opening the paper, a `running` run is shown as `paused` with `Tiếp tục`.
- `DESIGN.md`: document the batch panel. `docs/ROADMAP.md`: P2 🟨.

## 5. Tests (IDs in names)

- Prompts: each paper variant contains its role/neighbour lines and new version; without `PaperContext` the output equals
  the current prompts.
- `planRun`: skips non-body kinds with reasons; estimates per step and total; syntax batching by 40 sentences per section.
- `runBatch`: checkpoints, retry with backoff on 429/5xx and no retry on 4xx, budget stop with remaining pending, pause →
  resume continues at the right item and step, cancel, failed item does not stop the run, cache hit makes no calls,
  re-run keeps human decisions.
- Storage: migration, repository, origin `paper`, runs not in export.
- UI (fake client): estimate updates with selections; over-budget warning; consent before the first call; progress and
