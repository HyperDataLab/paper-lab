## 1. Core — `src/core/paper/`

- `PaperSchema` (Zod): `{ schemaVersion: 1, id, title, createdAt, updatedAt, source: { kind: 'pdf'|'latex'|'markdown'
|'text', fileName, pageCount|null, sha256 }, sections: Section[], paragraphs: PaperParagraph[] }`;
  `Section = { id: 'sec1', heading, role: 'title'|'abstract'|'introduction'|'methods'|'results'|'discussion'|
'conclusion'|'related_work'|'references'|'appendix'|'other', level, pageStart|null }`;
  `PaperParagraph = { id: 'sec2_p03', sectionId, order, text, pageStart|null, kind: 'body'|'caption'|'equation'|
'list'|'reference'|'heading_like', textHash }`. Paragraph text is immutable after import.
- `segmentPaper(lines | markdown | latex)`: headings detection (numbered `1`, `1.1`, `I.`, all-caps short lines,
  Markdown `#`, LaTeX `\section{}`), IMRaD role mapping from heading words (English; e.g. "Materials and Methods",
  "Experimental Setup" → methods; "Related Work", "Background" → related_work), paragraph joining with de-hyphenation
  across line breaks, caption detection (`Figure 3.`, `Table 2:`), reference-list detection after a References
  heading, equation-like lines. IDs are deterministic from position (`sec{n}_p{mm}`) so re-import gives the same IDs.
- Each body paragraph can be turned into the existing `TextAnalysis` with `analyzeText(paragraph.text)` — P1 does
  not run the pipeline, it only exposes this.

## 2. Parsing adapters — `src/shared/paper/`

- `pdfParser.ts`: PDF.js in a module worker; per page text items → lines (port `itemsToLines`), drop running
  headers/footers repeated on ≥ 50 % of pages, keep page numbers on paragraphs. File never leaves the browser.
- `latexParser.ts`: strip comments, expand simple `\input`-free single files, keep `\section`/`\subsection`/
  `\paragraph`, remove figure environments but keep `\caption{}` as caption paragraphs, keep math as `[math]`
  placeholders, drop the bibliography environment into reference paragraphs.
- `markdownParser.ts` and plain text: headings and blank-line paragraphs.
- Size guard: refuse files > 25 MB or > 200 pages with a clear message.

## 3. Storage

Dexie version bump: table `papers` (id, updatedAt, title) storing the full `Paper`; repository `papers.create/get/
list/delete` with audit actions `import_paper` / `delete_paper` (enum extended; old data valid). Export/import JSON
includes papers (formatVersion unchanged if additive; otherwise bump with a migration and tests).

## 4. UI — module group "Phân tích bài báo"

- Registry: new sidebar group `paper` ("PHÂN TÍCH BÀI BÁO") with module `paper-import` ("Tải bài báo", status
  `beta`) at `/papers` and a detail route `/papers/:id`.
- `/papers`: drop zone + file button (PDF, .tex, .md, .txt), privacy note "Tệp được xử lý trên máy của bạn, không
  tải lên máy chủ", progress per page for PDFs, list of imported papers (title, pages, sections, paragraphs, date,
  delete with confirmation).
- `/papers/:id` — **paper map**: left column section outline (role badge + heading + paragraph count); centre the
  paragraphs of the selected section in reading type, each with its ID and kind badge (captions, equations and
  references visually muted); right column a summary card (sections by role, body paragraph count, sentence count via
  `analyzeText`, words, pages) and a "Đánh giá đoạn này" action that opens Evaluate with that paragraph's text
  prefilled (no AI call). A banner states that batch analysis and AI review come in later slices.
- Editable section role (Select) because heading detection can be wrong; changing it is audited (`edit_label`).
