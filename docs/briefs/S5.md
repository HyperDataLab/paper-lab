## 1. Core (pure; no React, no fetch) — `src/core/analysis/`

- `syntaxTypes.ts`: `SyntaxProvider { analyze(text: TextAnalysis, signal?): Promise<SyntaxResult> }`;
  `SyntaxResult { provider; providerVersion; reproducible: boolean; sentences: SentenceSyntax[] }`;
  `SentenceSyntax { sentenceId; subject: TokenRange|null; subjectHead: number|null; mainVerb: TokenRange|null;
mainVerbHead: number|null; topic; action; stress (TokenRange|null); voice: 'active'|'passive'|null;
clauseCount: number|null; maxClauseDepth: number|null; confidence: number|null; unresolved: string[] }`.
  `TokenRange = { start; end }` are GLOBAL S2 token indexes, end exclusive.
- **Definitions** used in the prompt and the validator:
  - `subject` = the main-clause grammatical subject phrase (`The performance of the proposed model`);
    `subjectHead` = its head noun (`performance`).
  - `mainVerb` = the main-clause verb group: from the first finite verb or auxiliary to the lexical verb,
    **including** adverbs that sit inside the group (`was dramatically improved`); `mainVerbHead` = the lexical
    verb (`improved`). Distance is always measured to `mainVerb.start`.
  - `topic`, `action`, `stress` per Schimel: Topic = what the sentence is about (usually the subject, at the
    start); Action = what the topic does (main predicate); Stress = the new or important information, usually at
    the end.
- `validateSyntax.ts`: `validateSentenceSyntax(raw, text)` → `SentenceSyntax`. Any range that is empty or outside
  that sentence's `[tokenStart, tokenEnd)`, and any head outside its range, becomes `null` with a reason in
  `unresolved` (e.g. `subject: out of sentence range`). Unknown `sentenceId` → dropped. A sentence missing from
  the output → all-null entry with `unresolved: ['no model output']`.
- `metrics.ts` (deterministic, PRD §4), per sentence:
  - `subjectVerbDistanceTokens` = number of tokens with `!isPunctuation` strictly between `subject.end` and
    `mainVerb.start`. `null` if either is null, if `mainVerb.start < subject.end` (reason `atypical order`), or
    if they overlap (reason `overlap`).
  - `interveningSpan` = code-point span from the first non-punctuation token after the subject to the last
    non-punctuation token before the verb; `null` when the distance is null or 0.
  - `subjectSpan`, `verbSpan`, `topicSpan`, `actionSpan`, `stressSpan`: code-point spans from token offsets,
    never from the model.
  - `preTopicTokens` (non-punct tokens before `topic.start` in the sentence); `topicPositionRatio` =
    (topicSpan.start − sentence.start) / (sentence.end − sentence.start), 3 decimals; `stressEndDistance`
    (non-punct tokens after `stress.end` to sentence end). Null inputs → null.
- `heuristics.ts`: `SV_GAP_REVIEW = 8`, `SV_GAP_HIGH = 15`, `CLAUSE_DEPTH_REVIEW = 3` with the comment
  "product heuristics, need calibration; not Schimel thresholds"; `classifyGap(d)` →
  `'none'|'review'|'high'|null`. Labels only: **S5 creates no issues** (`issues` stays `[]`).
- `src/core/prompts/sentenceSyntax.ts`: add `sentenceSyntax: 'sent-syntax-1'` to `PROMPT_VERSIONS`.
  `buildSentenceSyntaxPrompt(text)` → `{ system, user }`. The user message lists each sentence as
  `s1: [0]The [1]performance [2]of …` with GLOBAL indexes. The system prompt (English) states the definitions
  above and must say: return token indexes only, never character offsets, never rewrite the text, use null when
  unsure, give a confidence 0–1 per sentence. Zod output schema `SentenceSyntaxOutputSchema`:
  `{ sentences: [{ sentenceId, subject, subjectHead, mainVerb, mainVerbHead, topic, action, stress, voice,
clauseCount, maxClauseDepth, confidence }] }` (ranges `{start,end}|null`).
- `src/shared/llm/llmSyntaxProvider.ts`: implements `SyntaxProvider` with the gated client; provider `llm`,
  `providerVersion = PROMPT_VERSIONS.sentenceSyntax`, `reproducible: false`; batches of ≤ 12 sentences per call;
  validates through core.

## 2. Schema and storage

Extend `SentenceAnnotationSchema` (schemaVersion stays 1; new fields nullable with defaults so S3 records still
parse): `subjectSpan`, `verbSpan`, `interveningSpan` (Span|null); `subjectHeadTokenIndex`,
`verbHeadTokenIndex` (int|null); `voice`; `clauseCount`; `maxClauseDepth`; `preTopicTokens`;
`topicPositionRatio`; `stressEndDistance` (number|null); `unresolved: string[]` (default `[]`).
`validateAnalysisSpans` checks the new spans too. On save, record `versions.prompt`, `versions.model` (from the
client meta), `versions.syntaxProvider = 'llm/sent-syntax-1'`, `contextLimited: true`.

## 3. UI — Evaluate

After "Tách câu": button "Phân tích câu (AI)" → `ensureConsent()` → run the provider, with "Huỷ" (AbortController)
and a skeleton per sentence. For each sentence:

- sentence text with subject (solid underline, `aria-label` "Chủ ngữ"), main verb (double underline,
  "Động từ chính") and intervening span (dotted, `--hl-structure`); render via UTF-16 conversion of stored spans;
- badge line `T: … · A: … · S: …` (text from the source via spans; null → "Chưa xác định"; confidence < 0.6 →
  dashed border and "?"), voice ("Chủ động"/"Bị động", descriptive only), clause count/depth;
- chip `Khoảng cách chủ–vị: N token` with "Cần xem lại (ngưỡng thử nghiệm ≥ 8)" or "Ưu tiên xem lại (≥ 15)";
  null → "—" with the `unresolved` reasons in a details element;
- banner "Thiếu ngữ cảnh: chỉ phân tích đoạn văn này (context_limited)".

Map errors as on the Settings page (cancelled consent → no message; 401; network; timeout; invalid output).
Saving includes annotations; reopening a saved analysis shows them without calling the LLM. Files < ~150 lines.
