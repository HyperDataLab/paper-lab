## 1. Core detectors (pure) — `src/core/detectors/`

- `lexicons.ts`: `DETECTOR_VERSION = 'det-1'` and `DEFAULT_LEXICON` (exported, typed `Lexicon`), with a comment
  "product lexicons, need calibration; customisable later". Matching is case-insensitive on token text, over
  consecutive tokens within one sentence. Contents (at least):
  - `fuzzyVerbs`: word forms of `conduct, perform, carry out, make, do, occur, involve, affect, impact, provide,
give, have, show, exhibit, undergo, achieve, obtain, utilize, facilitate` (list the inflected forms
    explicitly; multi-word entries such as `carry out`, `carried out` allowed).
  - `intensifiers` (→ `WEAK_MODIFIER`): `very, really, quite, rather, extremely, highly, truly, fairly, somewhat,
particularly, especially`.
  - `magnitudeIntensifiers` (→ `UNSUPPORTED_INTENSIFIER`): `dramatically, greatly, substantially, remarkably,
markedly, considerably, tremendously, hugely, vastly, enormously`.
  - `protectedQualifiers`: never flagged, even when another rule would match — `significant, significantly,
statistically, preliminary, approximately, about, likely, possibly, probably, may, might, suggest(s)`.
    A modifier token directly followed by a number token is also not flagged (`highly 3-fold` stays).
  - `nominalizationSuffixes`: `tion, sion, ment, ance, ence, ization, isation, ity`, plus a `nominalizationStop`
    list of common terms that are not actions (`information, population, function, environment, equipment,
evidence, experience, science, university, quality, quantity, community, section, condition, solution, …`).
  - `wordyPhrases`: `{ phrase, type: 'REDUNDANT_PHRASE' | 'METADISCOURSE', replacement: string | null }`, e.g.
    `in order to → to`, `due to the fact that → because`, `a large number of → many`, `at this point in time →
now`, `for the purpose of → to/for`, `has the ability to → can`, `in spite of the fact that → although`,
    `a total of → null`, `each and every → each`, `end result → result`, `future plans → plans`,
    `it is important to note that → null` (METADISCOURSE), `it should be noted that → null` (METADISCOURSE),
    `it is worth mentioning that → null` (METADISCOURSE).
- `detectLexical(text: TextAnalysis, annotations: SentenceAnnotation[] | null, lexicon = DEFAULT_LEXICON):
Issue[]`:
  - `FUZZY_VERB`: a fuzzy-verb match. If the match lies inside that sentence's annotation `verbSpan`, the issue
    span is the whole `verbSpan` (`were conducted`, role `verb`); otherwise the matched tokens (role `verb`).
  - `NOMINALIZATION`: a token ending in a listed suffix, length ≥ 7, not in the stop list, **and** either
    followed by `of` or preceded within 3 tokens by a fuzzy verb (`performed an evaluation of`). Role `noun`.
  - `WEAK_MODIFIER` / `UNSUPPORTED_INTENSIFIER`: the single modifier token (smallest causal span, role
    `modifier`), subject to `protectedQualifiers`.
  - `REDUNDANT_PHRASE` / `METADISCOURSE`: the matched phrase (role `phrase`); `suggestedFix` from `replacement`
    (`Thay bằng "to"` or `Có thể bỏ cụm này` when null).
- `detectStructural(text, annotations): Issue[]` (needs S5 annotations; returns `[]` without them):
  - `SUBJECT_VERB_GAP` when `classifyGap(subjectVerbDistanceTokens)` is `review` (severity `minor`) or `high`
    (severity `moderate`); span = `interveningSpan` (role `intervening_phrase`); metric
    `subject_verb_distance_tokens` / value / unit `tokens`; `sourcePrinciple: 'Schimel Ch. 12, §12.4'`;
    confidence = `parseConfidence ?? 0.5`.
  - `CLAUSE_DEPTH` when `isDeepClause(maxClauseDepth)`; span = the sentence span (role `sentence`); metric
    `max_clause_depth`; severity `minor`.
- `detectCandidates(text, annotations, lexicon?)` = structural + lexical, sorted by first span start then type,
  de-duplicated by `type + span`. Invariants for every detector issue: `status: 'candidate'`, `findingKind:
'review_candidate'` (`stylistic_suggestion` for `REDUNDANT_PHRASE` / `METADISCOURSE`), severity `minor` unless
  stated, `category = ISSUE_CATEGORY[type]`, lexical confidence `0.5`, `sentenceIds: [sentence.id]`,
  **deterministic id** `${type}:${sentenceId}:${start}-${end}` (code points of the first span). `why` and
  `suggestedFix` are short Vietnamese strings (the analysed text stays English); never claim a proven error.
  `sourcePrinciple`: Ch. 12 §12.4 (gap), Ch. 12 (clause depth), Ch. 14 §14.2 (fuzzy verb, nominalization),
  Ch. 16 §16.4 (modifiers), Ch. 16 (wordiness, metadiscourse).
- **Passive voice is never a detector output** (AC-09). Long sentences are never a detector output.

## 2. Contextual judgement (PRD §8 step 6)

- `src/core/prompts/candidateJudge.ts`: add `candidateJudge: 'cand-judge-1'` to `PROMPT_VERSIONS`.
  `buildCandidateJudgePrompt(text, annotations, candidates, context)` → `{ system, user }`. The user message has
  the full paragraph, the optional context before/after and audience (or "context not provided"), each
  sentence with its voice (from annotations), and the candidate list as `id | type | sentenceId | "exact span
text" | metric`. The system prompt (English) says: judge whether each candidate is actually a problem in this
  context; passive voice, hedges, necessary qualifiers and Methods-style procedure verbs can be appropriate; do
  not invent numbers, effect sizes, citations or facts; `suggestedFix` must keep claims, hedging, negation and
  numbers; write `why` in Vietnamese; return each given id once; do not add ids. It also asks, per sentence
  with `voice = passive`, whether the passive construction obscures the actor or action in a way that matters.
- `CandidateJudgeOutputSchema` (Zod): `{ judgements: [{ id, verdict: 'problematic'|'acceptable'|'uncertain',
severity: 'minor'|'moderate'|'major'|null, confidence: 0..1, why, suggestedFix: string|null }],
passive: [{ sentenceId, problematic: boolean, confidence, why, suggestedFix: string|null }] }`.
- `src/core/detectors/applyJudgement.ts`: `applyJudgement(candidates, output, text, annotations): Issue[]`.
  - `problematic` → `status: 'confirmed_by_model'`, severity from the model if given (never `critical`),
    model `confidence`, `why`, `suggestedFix` (fall back to detector values when null/empty).
  - `acceptable` → kept for traceability with `status: 'candidate'`, `findingKind: 'stylistic_suggestion'`,
    `severity: 'info'`, model `why` and confidence.
  - `uncertain` or missing → unchanged candidate.
  - Unknown ids, duplicate ids (first wins) and any attempt to change spans/type are ignored.
  - `passive` entries with `problematic: true` and a known sentence that is really passive in the annotations
    and has a `verbSpan` → new `PASSIVE_PROBLEMATIC` issue, span = `verbSpan` (role `verb`), status
    `confirmed_by_model`, severity `minor`, `sourcePrinciple: 'Schimel Ch. 14, §14.1'`, id
    `PASSIVE_PROBLEMATIC:${sentenceId}:${start}-${end}`. Passive entries that are not problematic create
    nothing.
  - Output goes through the same span validation as everything else (`validateAnalysisSpans` on save).
- `src/shared/llm/llmCandidateJudge.ts`: `createLlmCandidateJudge(client)` with
  `judge(text, annotations, candidates, context, signal?)` → `{ issues, model, promptVersion }`. Temperature 0,
  one call per ≤ 40 candidates (passive questions go in the first call). Zero candidates and no passive
  sentence → no call. Export from `src/shared/llm/index.ts`.

## 3. Schema and storage

- `Analysis.versions` gains `detectors` and `judgePrompt`, both `z.string().nullable().default(null)` so S3/S5
  records still parse. `repositories.analyses.create` accepts `issues?: Issue[]`. Saved analyses keep their
  issues and versions; reopening a saved analysis shows them **without** calling the model.

## 4. UI — `src/modules/evaluate/`

S7 builds highlights, the inspector and filters. S6 only needs a clear list:

- Lexical candidates appear right after "Tách câu" (no AI, computed locally). Structural candidates are added
  after "Phân tích câu (AI)". Editing the text or re-running syntax clears any judgement.
- A card "Ứng viên vấn đề (N)" grouped by category (Cấu trúc câu / Từ ngữ), each row: Vietnamese type label,
  the exact quoted span, metric (e.g. `9 token`), severity, a status badge (`Ứng viên`, `AI cho là có vấn đề`,
  `AI cho là chấp nhận được`), `why`, `suggestedFix`, `sourcePrinciple`. A permanent note: "Đây là ứng viên
  cần xem xét, không phải lỗi đã khẳng định." Status uses text + icon, not colour alone.
- Button "Đánh giá theo ngữ cảnh (AI)" (consent-gated, cancellable, error text via `describeLlmError`), shown
  when there is at least one candidate or passive sentence; show the `context_limited` notice as in S5.
- Hook `useCandidateJudge` mirroring `useSyntaxAnalysis` (run / cancel / reset / load).
- Save stores issues plus `versions.detectors` (`det-1`) and, after judgement, `versions.judgePrompt`
  (`cand-judge-1`) and the model.

## 5. Tests (IDs in names)

- `AC-03` PRD paragraph (§6): candidates are exactly `UNSUPPORTED_INTENSIFIER` on `dramatically`,
  `WEAK_MODIFIER` on `very`, `FUZZY_VERB` on `were conducted` (with S5-style annotations) / `conducted`
  (without); assert code-point spans with `sliceCp`. No `SUBJECT_VERB_GAP` (distance 6 < 8).
- `EV-03` gap 9 → minor, gap 15 → moderate, depth 3 → `CLAUSE_DEPTH`, null distance → none.
- `EV-05` `statistically significant`, `significantly`, `preliminary`, `highly 3-fold` are not flagged.
- `EV-04` nominalization rule (`performed an evaluation of` flagged; `information`, `population` not).
- `EV-06` wordy phrases and metadiscourse with replacements; multi-word match across sentence boundary is not
  allowed.
- `AC-09` passive sentences and long sentences produce no detector issue; `PASSIVE_PROBLEMATIC` only appears
  from a problematic judgement on a passive sentence with a verb span.
- `applyJudgement`: each verdict, unknown/duplicate ids, `critical` severity rejected, fallback texts, ids and
  spans unchanged. Deterministic ids are stable across runs.
- `llmCandidateJudge`: batching at 40, no call for zero candidates, versions returned.
- UI (fake client, like `syntax-ui.test.tsx`): candidates after split; consent before judgement; status badges
  after judgement; save → reopen shows issues and makes no model call.
- Keep coverage ≥ 90 % lines for `src/core/**` and `src/shared/llm/**`.
