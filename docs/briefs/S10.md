Principles: the source analysis is immutable (AC-12). A revision is a **new analysis** linked by
`parentAnalysisId`; nothing replaces the original without the user's explicit approval. The model proposes text;
**code** aligns the diff, computes every offset and runs the meaning-preservation checks. No new numbers, citations,
facts or claim-strength changes (WR-06, WR-08, AC-07).

## 1. Core — `src/core/revision/`

- `prompts`: `src/core/prompts/revision.ts`, `PROMPT_VERSIONS.revision = 'revise-1'`;
  `buildRevisionPrompt(analysis, selectedIssues, constraints)`; `RevisionOutputSchema`:
  `{ revisedText: string, changes: [{ issueIds: string[], before: string, after: string, rationale }],
needsEvidence: [{ issueId, note }] }` — `before`/`after` are quoted text, **never offsets**. System prompt
  (English): revise only to address the selected issues (listed with type, quoted span, why, suggested fix);
  preserve data, references, numbers, units, negation, hedging/modality and claim strength; never add evidence or
  values — put the issue in `needsEvidence` instead (e.g. an unsupported intensifier needs an effect size the text
  does not give: remove or soften, or ask, never invent); keep `preserveTerms` verbatim; return the full revised
  paragraph; rationale in Vietnamese.
- `align.ts`: `alignRevision(source, revised)` → word-level diff (implement a small LCS/Myers diff over the S2
  tokens of both texts; no dependency) producing hunks `{ kind: 'equal'|'insert'|'delete'|'replace', before: Span |
null, after: Span | null }` with code-point offsets into each text. `attachChanges(hunks, modelChanges)` links each
  model change to the hunks whose text matches `before`/`after` (exact match after whitespace normalisation);
  unmatched model changes are reported, hunks without a model change are flagged `unexplained`.
- `meaningChecks.ts`: deterministic checks between source and revised text, each `{ id, status: 'pass'|'fail'|
'warn', detail, spans }`:
  - `numbers_preserved`: every number token (incl. decimals, %, ranges, units next to them) in the source appears
    in the revised text with the same value, and no new number appears (fail);
  - `citations_preserved`: bracketed / parenthetical citations and `et al.` patterns preserved, none added (fail);
  - `negation_preserved`: counts of `not, no, never, neither, nor, without, cannot, n't` per clause-ish window do
    not drop (fail) ;
  - `hedging_preserved`: hedges and modals (`may, might, could, suggest(s), likely, possibly, appear(s),
approximately, about, preliminary`) not removed (warn) and none of `prove(s|d)`, `demonstrate(s|d) conclusively`,
    `definitely`, `always` added (fail — claim strength up);
  - `preserve_terms`: each user term still present verbatim (fail);
  - `length_change`: ratio reported (info only).
    Any `fail` blocks "Áp dụng" until the user explicitly overrides with a confirmation dialog that names the failed
    checks.
- `buildRevision(source, output, selected, constraints)` → `Revision = { id, sourceAnalysisId, sourceHash,
revisedText, revisedHash, hunks, changes, unmatchedChanges, needsEvidence, checks, appliedIssueIds, promptVersion,
model, createdAt }` (`appliedIssueIds` = selected ids that at least one matched change cites).

## 2. Schema and storage

- `RevisionSchema` (Zod) and a Dexie table `revisions` (DB version bump with migration; existing data untouched);
  repository `revisions.create/get/listBySource`. Audit actions added: `create_revision`, `apply_revision`
  (old data valid).
- "Áp dụng bản sửa" never edits the source: it creates a **new Analysis** from `revisedText` (fresh `analyzeText`,
  `parentAnalysisId = source.id`, title "Bản sửa của …"), records `apply_revision`, and opens it in Evaluate for
  re-evaluation (AC-08). The source analysis and its issues are unchanged (assert in tests).

## 3. UI — module `Chỉnh sửa` (`src/modules/revise`, currently a placeholder)

- Entry points: from Evaluate, a toolbar/panel action "Chỉnh sửa các gợi ý đã chọn" that is available on a
  **saved** analysis; in the suggestion panel each card gets a checkbox "Chọn để chỉnh sửa" (default: confirmed_by_human
  and confirmed_by_model issues pre-selected, dismissed never selectable). It navigates to `/revise?analysis=<id>&issues=…`.
- Revise page layout (three-column grid like Evaluate): left = selected issues list (removable) + constraints
  (`preserve_claims`, `preserve_hedging`, `no_new_facts` shown as locked-on checkboxes; `preserveTerms` input as
  chips); centre = **aligned diff** (side-by-side ≥ 1024 px, stacked below): original on the left / revised on the
  right with insert/delete/replace highlights (colour + strikethrough/underline, not colour only), each hunk
  linked to its change rationale and issue ids; right = meaning-check panel (pass/warn/fail with icon + text, spans
  highlighted on click) and `needs_evidence` list ("Cần bằng chứng từ bạn").
- Actions: `Tạo bản sửa (AI)` (consent-gated, cancellable), `Tạo lại`, `Sao chép bản sửa`, `Áp dụng bản sửa`
  (primary; blocked by a failed check unless overridden in a confirmation dialog), `Huỷ`.
- After apply: navigate to Evaluate with the new analysis; Evaluate shows a small "Bản sửa của <title>" link back to
  the source and to the revision.
- History page lists revisions under their source analysis.
- `DESIGN.md` §2 D: document the diff view. `docs/ROADMAP.md`: S9 ✅, S10 🟨.

## 4. Tests (IDs in names)

- `WR-07` alignment: insert / delete / replace hunks with exact code-point spans, including a non-BMP character and
  multiple spaces; model changes attached; unmatched changes and unexplained hunks reported.
- `AC-07` / `WR-06` / `WR-08` meaning checks: a changed number, an added number, a dropped citation, a dropped
  negation, a removed hedge (warn), an added "proves" (fail), a missing preserve term; all-pass case.
- `AC-08` apply creates a new analysis with `parentAnalysisId`, audit `apply_revision`, source unchanged (`AC-12`).
- Prompt text states the preservation rules and `needsEvidence` (assert).
- Provider: one call, versions returned, output validated.
- UI (fake client): select issues in Evaluate → navigate; consent; diff rendered with highlights; a failing check
  blocks Apply until the override dialog; apply opens Evaluate on the new analysis; History lists the revision.
- Coverage ≥ 90 % lines for `src/core/**` and `src/shared/llm/**`; all existing tests pass.
