Why: result extraction needs table cells with row and column. Today table rows become unrelated `list`/`equation`/`body` lines.

## 1. Schema (backward compatible)

- `PaperParagraph.kind` gains `table`; new optional `table: { caption paragraph id | null, rows: { cells: { text, column }[] }[], columns: number,
confidence: 'high' | 'low' }` and optional `equationLabel: string | null` for numbered equations.
- Old papers still parse (no migration of their paragraphs). Bump `parserVersion` on `Paper.source` (optional field, default null) to `paper-parser-2`.

## 2. Detection (`pdfParser.ts` / `segmentPaper.ts`)

- A table block: consecutive lines in one column or full width whose x positions fall into at least 2 stable columns over at least 3 rows, usually next to a
  `Table N` caption. Keep each cell's text verbatim, including `±`, signs, decimals and units.
- A row or column that cannot be aligned sets `confidence: 'low'`; never guess a cell. Merged or multi-line header cells stay as they are, with `confidence: 'low'`.
- Link the block to its caption when adjacent (above or below).
- Numbered equations: an `equation` paragraph ending in `(N)` gets `equationLabel: 'N'`, text unchanged.
- Table text stays searchable; the block's `text` is the rows joined so existing anchors keep working. Paragraph ids remain deterministic.
- Evaluate, batch and checks treat `table` like other non-body kinds. The map shows a table as an actual table, muted caption link, and a "Cần xem lại" badge when `confidence` is low.

## 3. Tests

Synthetic items: a regular table with `0.123 ± 0.004` cells (exact text, row and column); caption above and below; a two-column page with a table in one column;
a full-width table; a misaligned row → low confidence; a non-table aligned list stays a list; numbered equation label; deterministic ids; old papers parse; single-column regression;
map renders a table and the badge. Coverage ≥ 90 % lines for `src/core/**`.
