## 1. Layout (update `DESIGN.md` §2 to match)

- Column 1 is the existing sidebar (240 px / 64 px rail, drawer < 768 px). Do not change it.
- The Evaluate page uses the full width next to the sidebar (it is exempt from the shell's 1200 px content
  max-width; other pages keep it).
- Desktop ≥ 1280 px: CSS grid `minmax(0, 1fr) 380px`, gap 24 px. The centre column's reading area is capped at
  `72ch` and centred inside its column (comfortable line length for 17 px serif); the right panel is 380 px,
  sticky (`position: sticky; top: <header height>`), with its own scroll (`max-height: calc(100vh - header)`).
- 1024–1279 px: same grid with a 320 px panel.
- 768–1023 px: centre full width; the panel becomes a right `Drawer` opened by a "Gợi ý (N)" button in the
  toolbar (badge with the open count).
- < 768 px: single column; the panel is rendered below the text.
- No horizontal page scroll at any width ≥ 320 px. Colours only through theme tokens; light and dark both work.

## 2. Centre column "Đánh giá" (document)

- A toolbar row at the top (shared `Button`s, icons from `lucide-react`): `Tách câu` / `Chỉnh sửa văn bản`,
  `Phân tích câu (AI)`, `Đánh giá theo ngữ cảnh (AI)`, `Lưu vào lịch sử`, plus status text (running / saved) and
  the `context_limited` notice as a small muted line.
- Before splitting: the textarea (label "Dán một đoạn văn tiếng Anh"). After splitting: a **reading view** of the
  immutable source in `Source Serif 4` 17 px / 1.7 with inline issue highlights. "Chỉnh sửa văn bản" returns to
  the textarea (and clears analysis, judgement and decisions, as today when the text changes).
- Tabs under the toolbar (`shared/ui/Tabs`): `Văn bản` (reading view with highlights, default) |
  `Câu & số liệu` (the current S5 per-sentence view: subject/verb/intervening marks, T/A/S, gap chip, voice,
  clauses, the "Hiện token" toggle, source hash and versions). S5 syntax marks are not drawn in `Văn bản`, so the
  two highlight systems never overlap.
- Inline highlights follow `DESIGN.md` §3 exactly: category colour **and** line style (structure solid, word
  dotted, flow dashed, critical double + ⚠), weight by severity, `candidate` at 60 % opacity, confirmed at full,
  dismissed hidden in the text. Each highlight is a `<mark role="button" tabindex="0" aria-label="<nhãn loại>,
<mức độ>, <trạng thái>">`. Offsets go through one code point → UTF-16 helper; never compute offsets from DOM
  text.
- Overlaps: split the text into segments by all span boundaries; a segment covered by several issues shows the
  strongest style plus a small stacked second underline; clicking it selects the first issue, clicking again
  cycles through the others.
- Hover or focus on a highlight → the matching card gets a hover state; click / Enter / Space → that card is
  selected, expanded and scrolled into view in the panel. Selecting a card does the reverse (the highlight gets
  a selected outline and is scrolled into view).

## 3. Right column "Kết quả" — Grammarly-style suggestion panel

Reference: Grammarly's "Review suggestions" panel. Build it with our tokens and components, no Grammarly
branding, logo or copied assets.

- Header: title "Gợi ý" with the open-count badge; two tabs `Cần xem (N)` (status `candidate` or
  `confirmed_by_model`) and `Đã xử lý (M)` (`confirmed_by_human`, `dismissed_by_human`).
- Summary/filter row: chips per category with counts (`Cấu trúc câu`, `Mạch`, `Từ ngữ`, `Tổ chức đoạn`,
  hide empty ones) that toggle a filter; a second row `Tất cả | Đã xác nhận | Ứng viên` and a checkbox
  "Ẩn độ tin cậy thấp" (confidence < 0.5). Filters also hide the matching highlights in the text.
- **Collapsed card** (one line, like Grammarly): coloured dot + small category label · the exact span text (bold,
  truncated with ellipsis) · short type label (e.g. "Động từ chưa cụ thể"). AI-judged acceptable items
  (`severity: info`) are shown greyed with "AI: chấp nhận được".
- **Expanded card** (only one at a time): type label, status badge (text + icon: "Ứng viên cần xem lại",
  "AI cho là có vấn đề", "AI: chấp nhận được", "Đã xác nhận", "Đã bỏ qua"), `why`, then a suggestion box:
  - if the issue has a phrase replacement (REDUNDANT_PHRASE / METADISCOURSE from the lexicon, or an AI
    `suggestedFix` that is a rewrite): show the original span struck through and the suggestion beside it,
    Grammarly-style (`in order to` → `to`);
  - otherwise show `suggestedFix` as text prefixed "Gợi ý:".
    Then a details line: metric and value (`9 token`, `1 ứng viên`), the rule or threshold when there is one
    ("ngưỡng thử nghiệm ≥ 8"), severity (Vietnamese label), confidence (%), `sourcePrinciple`.
- Card actions: primary `Xác nhận`, secondary `Bỏ qua`, overflow/icon `Sao chép gợi ý` (clipboard, guarded by
  try/catch). In `Đã xử lý`: `Hoàn tác` (back to the previous status). There is **no "Accept / apply" that
  changes the text**: the source is immutable (AC-12); a muted hint says "Áp dụng sửa đổi sẽ có ở module Chỉnh
  sửa".
- A severity select in the expanded card (EV-11 "edit severity"): minor / moderate / major (critical is not
  offered).
- Empty states: no candidates → "Chưa có gợi ý" with a short explanation; all handled → "Đã xem hết gợi ý".
- The permanent note stays (small, at the bottom): "Đây là ứng viên cần xem xét, không phải lỗi đã khẳng định."
- Keyboard: cards are a list of buttons; ↑/↓ moves between cards when the list has focus; Esc collapses.

## 4. Decisions, persistence and audit (EV-11, AC-05, AC-06)

- `Xác nhận` → `status: 'confirmed_by_human'`; `Bỏ qua` → `'dismissed_by_human'`; `Hoàn tác` → previous status;
  severity edit changes `severity`. Spans, type, offsets and the source text never change.
- Add `'reopen'` to the audit `action` enum (keeps old data valid).
- Repository: `analyses.reviewIssue(analysisId, issueId, change: { status?; severity? })` updates the issue in one
  Dexie transaction with an audit event (`actor: 'human'`, action `confirm` / `dismiss` / `reopen` /
  `edit_severity`, `issueId`, `before` / `after` = the changed fields). Unknown ids throw; the record is
  re-validated through `AnalysisSchema` + `validateAnalysisSpans`.
- Saved analyses (`/evaluate?id=…`, currently read-only): decisions are allowed and written immediately through
  `reviewIssue`. Unsaved analyses: decisions are kept in page state; on `Lưu vào lịch sử` the issues are saved
  with their current statuses and one audit event per decision is written after `create_analysis`.
- A judgement re-run must not overwrite human decisions: issues whose status is `confirmed_by_human` /
  `dismissed_by_human` keep status and severity when the judge returns (merge by id).
